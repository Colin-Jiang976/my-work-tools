# 这次整理了什么

基于你提供的 10-15 快照制作独立审阅版，原始归档不修改。本轮只处理 MonitorTool；另一个下载文件归档工具后续单独处理。

## 保留的业务取舍

1. 工具负责打开文件、页面、辅助取用账号密码，人工核对文件名时间并检查内容。
2. 没有加入统一的 error 检测。不同日志的检查条件不同，有些 error 可接受，有些看 IP，有些看 ping NG 及容忍程度。无法把“搜到关键字”直接当作业务异常。
3. 周一仍按旧逻辑补开周末两天；三连休手动补查。保留已有流程，不引入日本节假日或任意日期范围计算。
4. 密码本是为减少反复打开本地 Excel、查找账号密码而增加的操作入口。没有自动导入 Excel，也没有实现自动登录。

## 这次实际改动

- 重写日文 README，补齐密码本、配置、周一规则和已知限制。
- 保留原日志筛选，抽出文件系统访问/打开动作；增加可固定时间、指定本地根目录和只预览的入口。
- 新增虚构日志生成器和周一演示，不需要访问公司网络，也不使用真实密码。
- 配置文件改用 config.example.json 分发，本地 config.json、secrets 和凭据文件加入忽略规则。
- 必需模块缺失、JSON 读取失败、班次切换时刻或件数不合法时明确停止。
- 读取目录和打开文件的失败显式提示；单目录失败仍尽量继续，不能把结束当成全部成功。
- 原密码文件解密/解析失败时停止，防止误当作首次使用而再次输入覆盖；BSTR 释放和密码菜单正常退出/异常退出的清理放入 finally。
- 增加无需外部测试框架的 Windows 检查脚本。

## 你现在怎么做

1. 解压为独立目录，先不要覆盖公司正在使用的文件。
2. 在该目录打开 Windows PowerShell，执行 `.\Run-Demo.ps1`。默认只显示会打开的文件。
3. 执行 `.\tests\Test-Tool.ps1`，把报错或最后的 PASS 发回来。
4. 演示版稳定后，再结合实际手顺确认配置与业务结果。

这不是现场已验收版本。原整理环境没有PowerShell；后来本人提供了Windows本地测试PASS，本轮不重复原测试。当前副本只新增URL配置校验，验证边界见VALIDATION.md及上级验证记录；公司网络、真实打开和完整密码菜单不能据本地测试认定已通过。
