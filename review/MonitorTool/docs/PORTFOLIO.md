# 求职展示整理（事实核对前草案）

## 可以讲清楚的经历

日次監視作業におけるログ閲覧準備と認証情報参照を PowerShell で省力化。AI を活用して初稿を作成し、制約のある環境への導入・エラー調査・業務手順に応じた改善を担当した。早番／遅番のログ選択、月曜の週末分確認支援、設定の外出し、監視画面の起動、アカウント情報の暗号化保存とコピー機能を実装。作成者を含む約4名で利用。

这段表述是基于你提供的信息和代码整理的草案。还没有确认“其他三个人各自使用了哪些功能”，因此面试时应按实际情况缩小陈述范围。

## 面试中最值得解释的判断

- 为什么不自动判断日志内容：不同日志存在不同的业务条件和容忍标准，人工复核保留。
- 为什么加密码本：原本每次需要打开本地 Excel 查找，工具把重复取用动作集中到入口。
- 为什么先做周一而没有做所有节假日：约4人使用、熟悉业务，复杂例外人工补查。
- 为什么重构：后续增加页面和密码本，配置与功能分离有助于继续维护。
- 如何使用 AI：初稿辅助生成；实际部署、故障排查、业务适配需要自己完成。不要把所有代码声称为逐行独立编写。

## 还需核实后才能写入简历的量化结果

- 改进前后耗时：按早晚各一次还是每日合计？人工检查时间和工具节省时间分别是多少？
- 四人是否都持续使用，使用哪些功能？
- 具体一次排错：现象、定位、修改、如何确认恢复。
