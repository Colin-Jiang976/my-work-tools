# MonitorTool — 日次監視作業支援ツール

Windows PowerShell 5.1 向けの、ログを開く・監視画面を開く・アカウント情報を参照するための補助ツールです。ログ内容の正常／異常判定は担当者が行います。

**このパッケージは 10-15 提供版を基に整理したレビュー用コピーです。現場環境での動作確認は未実施です。** 元のファイルや稼働中のツールに直接上書きせず、まずデモで確認してください。

## 背景と役割

- 別の PowerShell 処理が本番環境からログを取得し、毎日 08:50 と 16:50 に所定フォルダーへ配置します。本ツールは取得処理を実装しません。
- 担当者は早番・遅番に応じて必要なログを開き、ファイル名の日時と内容を確認します。
- 月曜午前は当日のログに加え、土曜・日曜分も開きます。三連休などは担当者が手動で補完します。
- 利用者は作成者を含む約 4 名。業務知識のある少人数チーム向けの補助です。

## まずローカルデモを実行

ZIP を展開し、そのフォルダーで Windows PowerShell を開きます。

```powershell
.\Run-Demo.ps1
```

架空のログを作り、2026-10-19（月）09:00 の選択結果を表示します。ネットワーク共有、ブラウザー、認証情報、クリップボードは使用しません。`Run-Demo.cmd` からも起動できます。実行ポリシーで拒否された場合は、その環境で許可された方法に従ってください。

ファイルも開く場合（関連付けされたアプリが複数起動します）：

```powershell
.\Run-Demo.ps1 -OpenFiles
```

デモのファイル数や名前は架空であり、現場の正解を表すものではありません。日時判定を再現するため、生成時にファイルの更新日時を設定します。

## 実環境用の設定

```powershell
Copy-Item .\config.example.json .\config.json
notepad .\config.json
.\Start-Tool.ps1 -Preview
```

`ServerIP`、共有名、件数、例外フォルダー、URL、`AccountKey` を実際の手順に合わせます。`-Preview` は選択結果のみを表示し、設定の書換え・ファイル起動・ページ起動・パスワード参照は行いません。ネットワーク共有の読み取りは行います。通常起動は `.\Start-Tool.ps1`。ページ不要なら `-SkipPages`。

ショートカットは `.\Install-Shortcut.ps1` で `shortcut` フォルダー内に作成されます。元の起動方式を継承して `ExecutionPolicy Bypass` を指定します。組織で許可された運用に合わせてください。

### 設定項目

| 項目 | 意味 |
|---|---|
| ServerIP | ログ共有先のサーバーアドレス |
| ShiftSplitHour | 早番／遅番の切替時刻（例：13） |
| MorningShift / EveningShift | 共有フォルダー名と開く件数 |
| OffsetFolders | 遅番では最新から 2 件スキップし、3 番目を 1 件開く対象。フォルダー名末尾で照合 |
| MorningPages | 午前中に開く URL とアカウントの参照キー |

例示用の `ShareFolderX/Y` は既定の班別リストに含まれていません。例外を利用する際は対象フォルダーを班別リストにも指定してください。デモ設定では照合可能な例を用意しています。

## パスワードブック

以前は PC 上の Excel ファイルを毎回開いて認証情報を探していました。その操作を減らす目的で、監視ページに必要なアカウントをメニュー表示し、番号でパスワード、`u1` 等でユーザー名をコピーします。

初回参照時に入力して保存できます。`.\Initialize-Secrets.ps1` から明示的に登録・更新もできます。レビュー版ではアカウントキーを英数字・`_`・`-` に限定しています。

保存には Windows DPAPI を利用します。同じ Windows ユーザー・PC で利用する前提です。Excel からの自動移行、ブラウザーへの自動ログイン、パスワード共有機能はありません。

保存データの復号に失敗した場合、既存ファイルを上書きせず停止します。コピーした場合はメニュー終了処理で現在のクリップボードを空にします。ただし強制終了や OS のクリップボード履歴まで消す保証はありません。同一 Windows セッションでの不正アクセスから守る仕組みではありません。

`config.json`、`secrets/`、`*.cred` は Git 管理対象外です。既に追跡しているファイルを `.gitignore` だけで追跡解除することはできません。公開用には例示設定のみを使用します。

## 選択ルールと既知の制約

10-15 版の選択方式を維持しています。ファイル名を解析せず **LastWriteTime の日付** で絞り、更新日時の降順に指定件数を選びます。午後の例外は 2 件スキップして 1 件取得します。月曜午前には日曜・土曜について早番／遅番ルールを追加適用します。

- 週末の早番／遅番は時刻別の絞り込みではありません。同じファイルが重複して選ばれる可能性を含め、従来方式を変更していません。担当者が日時を確認します。
- 必要数より少ないとき、ある分は開きます。件数充足の自動判定は追加していません。
- 読めないフォルダーや開けないファイルは警告し、可能な範囲で続行します。部分的に失敗してもプロセス終了コードは 0 になり得ます。警告の確認が必要です。
- 設定や必須モジュールの異常は停止します。
- 三連休、祝日、任意の未確認期間は自動計算しません。
- 内容検査はしません。許容される error、確認対象 IP、ping NG の許容範囲などがログごとに異なるため、担当者が業務手順に従って判断します。

## 構成

`Start-Tool.ps1` が入口、`modules/` が各機能、`demo/` が架空データ、`tests/` が検証、`docs/` が設計理由・変更履歴・求職向け整理です。

このコピーでは MonitorTool のみ整理しています。別系統のダウンロード済みログの整理ツールは含みません。
