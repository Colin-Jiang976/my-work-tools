这份独立副本用于改进和演示现有用途，没有迁移原Git仓库，也未替换工作中的版本。

| 工具 | 负责什么 | 不据此声称什么 |
| --- | --- | --- |
| MonitorTool | 选择并打开局域网日志、辅助打开监视页与取用账号 | 不下载AWS日志，不代替业务内容判断 |
| RdsLogArchive | 整理已经手动下载的四份RDS日志、给出关键词提示、可选备份 | 不连接AWS下载；无关键词不等于业务正常 |

两者作为不同作业辅助工具分别保留，不假设是同一条上下游链路。原先的业务项目名称不用于这份展示副本。

## 本轮实际改动

MonitorTool沿用已整理、本人已跑过本地测试的版本，只新增监视页面URL校验、使用中性示例网址，并更新验证说明。原版已经正确传递固定时间，本轮没有为它另改时间逻辑。原测试不重复运行，也不把本次测试说成已验证公司网络或完整密码菜单。

RdsLogArchive沿用四份文件、两份一组的处理方式，做了以下调整：

- 输入为配置中明确列出的四个文件，不再自动扫描真实Downloads里“刚好四个”的文件。
- 两组默认叫Group1/Group2；本人已确认分别对应主DB、备用DB，每组A/B两份，均手动从RDS下载。示例按主A、主B、备用A、备用B的落盘文件顺序配置，不代表AP与RDS两种来源。
- 默认预览。明确加`-Apply`后复制归档，保留源文件；同日目标已存在、改名撞名、缺文件等均停止，不覆盖旧档。
- 仅清理浏览器常见的` (数字)`后缀，`_1`可能属于原始名字，保留。输出清单保留改名前后对应和SHA256。
- err/ORA只输出匹配行数，继续人工按业务手顺检查；不输出“可以安心收工”。文件不会默认弹开。
- 网络备份默认关闭。只有明确配置并加`-Backup`时才尝试；备份失败会返回失败，同时保留已完成的本地归档。

## 先看演示

两个目录各有`Run-Demo.cmd`，双击即可运行各自的虚构材料预览。它只对该PowerShell进程设置执行策略，不修改系统设置。

RdsLogArchive也可在PowerShell中运行：

```powershell
.\RdsLogArchive\Run-Demo.ps1
.\RdsLogArchive\Run-Demo.ps1 -Apply
```

第一条生成虚构文件并预览归档计划，第二条在另一个独立演示目录内实际复制、校验和输出摘要。两者均不扫描真实Downloads、不连接AWS/共享目录、不打开程序。演示运行目录会留在RdsLogArchive/demo-runs中，便于本人看输入和输出。
